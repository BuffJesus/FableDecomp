# Modern engine architecture and ownership

Design contract, 2026-10-18. Applies to new runtime work in `rebuild/modern/`.
This is a target architecture; the status table below distinguishes existing
libraries from interfaces and ownership machinery still to be implemented.
The [modernization plan](MODERNIZATION.md) retains the full-game completion gate.
Bounded libraries can mature before that gate opens.

## Responsibilities and dependencies

Modules mean ordinary CMake libraries with headers and sources. C++ named modules
are a separate tooling choice. Keep existing directories until a move serves an
implemented boundary; do not create empty libraries for this diagram.

| Module | Responsibility | Allowed engine dependencies |
|---|---|---|
| formats | Retail formats, explicit codecs, unknown-byte preservation | Small value types and codec libraries; no running game |
| assets | Asset lookup, CPU decoding, cache and decoded-data lifetimes | formats; file capability supplied by app |
| simulation | Live entities, combat, AI, navigation, gameplay rules | Small value types, immutable gameplay data; no OS, GPU, Lua or disk layouts |
| quests | Script runtime, quest state and scheduling | Narrow quest-facing capability interfaces; no concrete world/managers |
| presentation | Extract transforms, lights, effects, HUD, draw and frontend requests | Read-only simulation views, asset IDs/leases; no simulation mutation |
| render | Drawing, GPU resources and backend implementation | Prepared presentation data and platform capabilities; no gameplay traversal |
| platform | Files, devices, OS clocks, audio/video backends | Small value types; no gameplay rules |
| integration | Save-to-world conversion, script bindings, presentation extraction | The specific modules each adapter connects |
| app | Startup, shutdown, session transitions, scheduling, implementation selection | Composition of the above; no accumulating gameplay rules |

An interface dependency is explicit, including callbacks and injected capabilities.
An assets file reader or render surface interface must not introduce a dependency
on the concrete Windows backend. Shared interface/value headers must stay small
and independently usable. Do not collect managers and game types into `core/`.

Each target declares public include roots and links. Private headers stay in its
source/private tree. Reusable libraries cannot depend on app or editor targets.
No cycles are allowed, including cycles hidden behind broad service contexts.
Public modern runtime APIs cannot expose retail layout headers or compatibility
snapshot classes. Reconstruction adapters are an explicit exception at the
integration boundary, never a dependency of the format libraries.

## Ownership and lifetime contract

Every new public service documents creation, destruction, permitted mutation,
borrow duration, thread confinement, and failure behavior before callers store it.

| Owner | Creates and destroys | Other systems receive | Mutation rule |
|---|---|---|---|
| Session/application | Simulation, quest runtime, adapters and backend instances | Narrow service references valid for the session | App coordinates startup, transitions and shutdown |
| Simulation | Live entities and their gameplay state | Validated runtime handles and bounded read-only views | Simulation operations perform state changes |
| Asset store | Decoded CPU data and cache entries | Asset identifiers or documented retained leases | Store controls replacement and eviction |
| Renderer | GPU objects and pending retirements | Resource/asset identifiers and prepared draw data | Renderer retires resources after GPU completion |
| Quest runtime | Script instances, quest state and scheduled work | Explicit quest operations and entity handles | Script bindings validate handles on each use |
| Presentation adapter | Reusable extraction buffers | A prepared frame view | View expires at documented consumption/reset point |

Persistent IDs and runtime handles are different types. Retail UIDs retain their
format semantics; handles use a slot and generation with validation on access.
The bounded `ThingStore` now validates slot/generation/owner handles, retires
slots rather than wrapping generations, and preserves identity across clear/reuse.
Save/load remapping and complete gameplay/component ownership remain open. See
[THING_STORE](THING_STORE.md). Long-lived entity pointers and indiscriminate shared ownership are not the
default. Useful recovered classes and algorithms can remain; ECS is not required.

Borrowed views cannot silently become retained references. Initially, simulation,
scripts and extraction run on one thread. Reusable buffers have explicit size
limits, overflow behavior and consumption lifetimes; parallelism is a later change.
Shutdown stops script work and extraction before destroying their simulation;
GPU retirement completes before renderer/device teardown.

## Capabilities, ordering and time

Quest bindings provide only evidenced operations such as finding a persistent ID,
reading position/health, spawning, awarding an item and starting dialogue. Split
interfaces by actual consumer needs. Do not pass an unrestricted world or an
EngineContext containing all managers. Lua types stay inside quest/binding code.
The [scripting design](../engine/SCRIPTING_REDESIGN.md) supplies the runtime plan;
these ownership constraints apply when connecting it to modern gameplay.

Immediate results use typed calls. Completed facts such as entity death or region
entry may use explicit events with documented delivery and subscriber lifetimes.
Preserve retail call order, reentrancy and visibility of state changes. Do not
introduce a universal event bus or blanket end-of-frame deferral.

[FRAME_TIMING](FRAME_TIMING.md) establishes a 15 Hz world update and interpolated
rendering. Platform clocks report elapsed real time. Application scheduling uses
that time and initially preserves retail present-completion prediction, the strict
PC53-rounded reciprocal conversion and strict `frames_ahead > 1` test, and at most one tick per update call.
The exact arithmetic and eleven counterexamples to direct multiplication are qualified in
[SERVER_UPDATE_POLICY](SERVER_UPDATE_POLICY.md).
Simulation advances one explicit world tick; presentation interpolates states.
`WorldClock` currently lives in platform for historical reasons but is scheduling
policy, with no OS calls. Its relocation is separate from changing its behavior.
Preserve RNG state, stream selection and consumption order. New per-subsystem
generators require evidence of equivalent behavior, not just matching seeds.

## Formats and rendering

Keep retail data, live runtime structures, and validating conversion code separate.
Opaque saved entity streams can round-trip without being executable entity state.
Loading live entities needs relationship validation, persistent-ID remapping and
owned lifetimes before it earns a session-load claim.

Use one authoritative headless implementation per format shared with FableForge.
Choose a pinned source/package arrangement before importing it. Neither project
may depend on the other's application; format ownership is settled per library.

Presentation prepares transforms, mesh/material identifiers, lights, effects and
UI data. Render backends consume that view without traversing CWorld or asking
creatures about quests. Design the interface from measured D3D9 usage. The title
viewer remains a texture-upload/presentation probe; it does not define the game loop.

Separate include roots enforce the portable/Win32 input boundary. The modern
CMake entry point now exports its configured targets to `architecture-targets.tsv`
and runs `tools/modern/check_modern_boundaries.py` during configuration and normal
builds (`fable_architecture_check`). It also runs through CTest and the existing
Windows/Linux workflow. Python 3.10 or newer is required for all modern configurations.

The gate rejects target cycles, unregistered modern libraries, dependencies outside
each library's policy, dependencies from reusable libraries back into applications,
and unexpected public include roots. Alias names, link-only dependencies, interface
sources and direct-interface dependency injection are checked. A new library must
have a reviewed policy before the tree configures; creating a runtime target cannot
silently bypass these rules.

For modern portable sources and public headers, direct literal includes must resolve
to the standard library, approved implementation dependencies, or declared modern
public headers. Private includes cannot cross module boundaries or enter public APIs.
Win32 backend headers require the backend target. Retail layout includes stay confined
to reconstruction/integration. Third-party implementation headers such as zlib do not
enter format public interfaces. Conditional includes are checked even in inactive
branches; macro includes and unsupported CMake generator expressions fail for review.

The source check is conservative, not a compiler dependency scanner. It does not
prove semantic ownership, absence of hand-declared foreign types, or dependencies
hidden inside third-party headers. Generated/canonical reconstruction internals remain
explicit exceptions. Public API design and runtime lifetime/ordering tests still need
review. The initial `fable_simulation` target declares no engine dependencies or external
implementation headers. It exposes owned value snapshots and validated handles;
gameplay code must extend that boundary deliberately.

|---|---|---|

| 5 | Representative headless game session | Same simulation library intended for graphical app; real owned objects, explicit ticks and expected state transitions |
| 6 | Presentation and platform/render/audio backends | Session behavior remains stable; measured visual/audio checks pass |

Stages can overlap for independent mature libraries. A borrowed-object replay
fixture does not satisfy stage 5. Select its representative gameplay scenario
after required entity creation, destruction, dispatch and RNG behavior are recovered;
document any remaining substitutes rather than claiming a complete game session.

Replay observations use stable IDs and explicitly serialized fields, never raw
modern object memory. Report the first differing tick, entity, field, expected and
actual value. Use verified retail package/checksum semantics as additional evidence;
an aggregate checksum is insufficient to locate a mismatch. Specify float tolerances
per observed behavior; checksum-sensitive x87 behavior may require exact semantics.

## Owned component implementation, 2026-10-18

ThingStore now lazily owns unique component collections and their ordered state;
a session queue holds weak component handles. Every handle includes parent,
interface type, generation and collection identity. Copy-returning snapshots
preserve callback visibility without exposing object pointers. The queue outlives
collections; component destruction precedes UID/list removal, and container cleanup
follows it. Factories receive parent handles and transfer unique ownership, with
typed portable parameters and no engine context. The complete component replay
