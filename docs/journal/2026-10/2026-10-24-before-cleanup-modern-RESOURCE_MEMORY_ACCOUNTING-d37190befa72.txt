# Resource memory accounting

`fable_assets::ResourceMemoryAccounting` owns prepared size and membership
values. Snapshot labels are 64-bit values local to one owner, not pointers,
leases or persistent resource identities. The class owns neither resources nor
decoded data and makes no allocation-budget or eviction decisions.

The native `CResource::SetResourceSize` body at `009fbf20` updates a resource's
size on every call. When a resource belongs to a list, it subtracts the previous
size and adds the replacement to the manager's allocated word. An unlisted
resource's size changes without contributing to that word. The original body
uses 32-bit arithmetic; the observed counter is treated as a raw word rather
than evidence of signed budget semantics.

The portable owner deliberately stores both sizes and the listed total as
`uint64_t`. Replacement subtracts the old contribution before checking the new
one, so a same-size replacement at the maximum total succeeds. A total above
`UINT64_MAX` fails before changing either the record or the total. Unlisted
records may hold any `uint64_t` size without contributing. Unknown labels also
fail before mutation.

`load_snapshot` consumes a vector of entries, builds an index, checks unique
labels and sums listed sizes with overflow checks before swapping in the new
state. Rejection and allocation exceptions preserve the previous state. Returned
snapshots are value copies. Owners cannot be copied or moved; use is confined to
one thread. `set_size` and `listed_bytes` allocate nothing and call no backend.
Membership replacement is explicit; there is no claim of live resource-list
registration or integration with `ResourceRecency` yet.
