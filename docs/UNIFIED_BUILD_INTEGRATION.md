# Unified Fable Build — Integration into the RE Hub

*Integrated 2026-07-20. Source: `D:\Downloads\UnifiedFable.rar` (3.4 GB, RAR5), the
"Unified Fable Build" by AlbionSecrets — the Fable TLC **PC debug editor** (`ego_r.exe`
class) patched to read **RETAIL `.big` banks**. No game exes ship inside (you supply
`Fable.exe` / `ego_r.exe` / `FableWin.exe`); it carries a `dinput8.dll` proxy + debug CRT
(`msvcr100d`). Read-only w.r.t. the game install; the high-value small files are staged
into `D:\Documents\FableTLC\unified_build\`.*

**The single most valuable thing:** the `Data\Defs\RetailHeaders\*.h` set + `banks.ini`
together are the **complete, canonical `SYMBOL → bank-slot-id` link table** the editor's
def-compiler uses to turn a text `.def` reference like `Graphic.BankIndex MESH_QUEST_SCROLL`
into a numeric bank index — and to know which `.big` that index lives in. This is the exact
name→id layer native APPEND has been missing. It confirms and *completes* the enum dump we
already had at `ghidra_out/installed_game/header_enums.csv` (which had the enums but not the
bank↔header↔`.big` binding, nor the path-keyed remainder slots).

## 2. The RetailHeaders symbol→id system + banks.ini mapping — **the append key**

### 2a. Header shape (auto-generated by `BankCreator`)

Every `RetailHeaders\*.h` begins `/* This file was auto-generated by BankCreator */` and is a
C-style `enum` mapping `SYMBOL = <bank slot index>`. The index is the **1-based slot in that
`.big` bank**. Two structural halves:

1. **Active named enum(s)** — the symbols def sources / engine code reference *by name*.
   e.g. `pc\textures.h` → `enum EEngineGraphic { GRAPHIC_SWIPE_01 = 7, ... }` (3683 named
   symbols); `meshdata.h` → `enum EAnimType2 { ... }` + `enum EMeshType2 { ... }`;
   `fonts.h` → `enum EFont { ENG_TAHOMA_10 = 1, ... }`; `pc\gui_bank.h` → `enum EGuiGraphicBank`.
2. **Commented-out `_1` remainder block** — the *remaining* slots that have no code symbol,
   keyed by **source-asset path**, e.g.
   `[\FABLETLC\...\PARTICLES\TEXTURE\GLOWING_CIRCLE_01.TGA] = 4577`.
   Header comment: *"So we can see all the graphic indices … Warning: Do not uncomment!"*

**Verified for `pc\textures.h`:** named block = 3683 ids, commented block = 2607 ids, IDs are
**disjoint**, union is **contiguous 1..6290**. So the header enumerates the *entire* bank slot
space; named symbols are the linkable subset. **`meshdata.h` is fully contiguous 1..8112**
(8112 mesh/anim symbols, no gaps). `EEngineGraphic` ids are sparse (gaps, e.g. 23→30) — those
gaps are real retail slot indices and must be honoured.

> **Append rule this establishes:** the next free append slot in a bank = `max(all ids)+1`
> (textures.big → 6291, graphics.big meshes → 8113). To make a new asset referenceable from a
> `.def`, it needs a *named* entry in the active enum; a path-only slot is reachable only by
> index. Symbol is the primary key; the id is positional.

### 2b. `banks.ini` — bank ↔ header ↔ `.big` binding

`unified_build\UnifiedFable\banks.ini` is what the installed header dump lacked: it binds each
retail `.big` to its `.bbb` bank export and its `.h` symbol header. Grammar:

```
RetailHeaderDirectory "data\defs\RetailHeaders\"
BeginRetailFile "data\graphics\pc\textures.big"
    GBANK_MAIN_PC="data\graphics\pc\textures.bbb", "pc\textures.h"
    GBANK_GUI_PC ="data\graphics\pc\gui_bank.bbb", "pc\gui_bank.h"
EndRetailFile
BeginRetailFile "data\graphics\graphics.big"
    MBANK_ALLMESHES="data\meshes\meshdata.bbb", "meshdata.h"
    MBANK_ENGINE   ="data\meshes\engmesh.bbb",  "engmesh.h"
EndRetailFile
```

| `GBANK_GUI_PC` | `pc\gui_bank.h` | `data\graphics\pc\textures.big` | `EGuiGraphicBank` | 34 |
| `MBANK_ALLMESHES` | `meshdata.h` | `data\graphics\graphics.big` | `EAnimType2`+`EMeshType2` | 8112 |

> the `.big` that id indexes. That is the entire "name → id → container" resolution the editor
> performs at compile time, now in hand as plain text.

## 3. Text-`.def` grammar (with quest-card + region examples)

The def sources compile into `game.bin`/`frontend.bin`. Grammar is a flat, brace-free block
language:

```
#definition          <TYPE>  <NAME> [specialises <PARENT_TEMPLATE>]
    <Field>          <value|SYMBOL>;
    <Sub.Field>      <value>;
    Components.Add("<CTComponentClass>");
    <ComponentDef>...<\ComponentDef>          // angle-bracket component blocks
#end_definition

#definition_template <TYPE>  <NAME>            // template variant, referenced by `specialises`
    ...
#end_definition
```

Values are either literals (`TRUE`/`FALSE`, floats, ints, quoted strings) or **symbols** that
resolve through the RetailHeaders (`MESH_QUEST_SCROLL`, `ENGINE_GRAPHIC_STATIC_MESH`,
`TXT_REGION_BANDIT_CAMP_DESCRIPTION`, `HUD_ICON_SCROLL`). Top `#definition` TYPEs by count in
this dump: `OBJECT` 3275, `UI` 2252, `CREATURE` 491, `ENGINE_THEME` 465, `BUILDING` 387,
`CREATURE_GENERATION_FAMILY` 156, `THING` 139, `BRAIN` 113, `REGION` 102, …

### 3a. REGION (`region.def`) — 102 defs

```
#definition  REGION  REGION_BANDIT_CAMP
    EnvironmentTheme          ENVIRONMENT_THEME1;
    InternalEnvironmentTheme  ENVIRONMENT_INTERNALS;
    HasSea                    FALSE;
    Music                     MUSIC_SET_BANDIT_CAMP;
    UseCrimes                 TRUE;
    WorldMapOffsetX           612.0;
    WorldMapOffsetY           1566.0;
    NameGraphic               WORLD_MAP_NAME_GRAPHIC_BANDIT_CAMP;   // → graphics bank symbol
    RegionDescription         TXT_REGION_BANDIT_CAMP_DESCRIPTION;   // → text bank symbol
#end_definition
```

### 3b. QUEST CARD (`objects_gameplay.def`) — the authoring target

A card is an `OBJECT` that `specialises OBJECT_QUEST_CARD_TEMPLATE` and carries a
`<CQuestCardDef>` component block. Template (`#definition_template OBJECT OBJECT_QUEST_CARD`)
excerpt + a concrete instance:

```
#definition_template OBJECT OBJECT_QUEST_CARD
    Components.Add("CTCTargeted");
    Graphic.Type          ENGINE_GRAPHIC_STATIC_MESH;
    Graphic.BankIndex     MESH_QUEST_SCROLL;          // meshdata.h symbol
    Graphic.AdditiveAlpha TRUE;
    Components.Add("CTCQuestCard");
    <CQuestCardDef>
        InventoryCategory INVENTORY_CATEGORY_QUEST_CARD_BLANK;
        NumBoasts         0;
    <\CQuestCardDef>
    Components.Add("CTCInventoryItem");
    <CInventoryItemDef>
        Graphic.BankIndex HUD_ICON_SCROLL;            // pc/textures.h (EEngineGraphic)
    <\CInventoryItemDef>
    GroupDef              GO_GAMEPLAY;
#end_definition

#definition OBJECT OBJECT_QUEST_CARD_PROTECT_FARM specialises OBJECT_QUEST_CARD_TEMPLATE
    Graphic.BankIndex     MESH_QUEST_CARD_CORE_GOOD_01;
    <CQuestCardDef>
        QuestName         TEXT_QUEST_PROTECT_FARM_TITLE;     // text.h EGameText
        QuestSummary      TEXT_QUEST_PROTECT_FARM_SUMMARY;
        RegionName        "OrchardFarm";                     // CDefString, not a symbol
        IsCoreQuest       TRUE;
        GoldReward        750;
        RenownReward      400;
        RewardObjects[0]  OBJECT_TROPHY_WHISPER_BROOCH_01;   // OBJECT def ref (by name)
        NumBoasts         5;
    <\CQuestCardDef>
#end_definition
```

This is the exact source form of the pair our `forge::questcard` clones at the binary level:
the `OBJECT` (addressable by name from FSE `Quest:AddQuestCard`) + its `<CQuestCardDef>` (the
content). The `.def` shows every scalar field name and which ones are symbol refs vs literals
vs `CDefString` — a direct schema oracle for the card patcher.

## 5. What this unblocks / validates

1. **Native APPEND, def side — name→id is now in hand.** To emit a `.def`-equivalent binary
   reference to a mesh/graphic/text/particle by *name*, look the symbol up in the matching
   `RetailHeaders\*.h` enum → get the slot id; `banks.ini` tells you the id's `.big`. This is
   the layer `forge::bin` needed to move beyond donor-cloning toward authored references.
   Recommendation: parse the RetailHeaders into a `forge` symbol table (name→id per bank) and
   join it to `banks.ini`; cross-check against `ghidra_out/.../header_enums.csv` (already
   matches on counts).

2. **Bank APPEND is now scoped.** `max(id)+1` per bank is the append slot (textures→6291,
   meshes→8113). A new *named*, def-referenceable asset also needs a symbol added to the
   active enum. `forge::big` currently reads but does not mutate bank payloads — this defines
   the id/symbol bookkeeping a future bank writer must do.

3. **Quest-card authoring validated.** The `.def` source is the field-level oracle for
   `forge::questcard`'s `CardPatch`: confirms which fields are safely patchable scalars
   (`QuestName`, `GoldReward`, `IsCoreQuest`, `NumBoasts`, …) and which are opaque
   `CDefString`/collection fields that must be clone-preserved (`RegionName`, `RewardObjects`,
   `InventoryCategory`). Pair with the open offset-85 self-ref fix in `APPEND_ALGORITHM.md`.

4. **Baker oracle run is fully configured.** The staged `dbugst.ini` / `dbug.ini` /
   `edit_settings.ini` are the exact editor config for the `BAKE_FORGETEST_TERRAIN.md`
   bake-and-diff plan (generate `FinalAlbion_RT.stb`, extract the ForgeTest chunk as a
   byte-exact oracle for the quadtree grammar still open in `forge::stbbake`).

5. **RetailHeaders == DevHeaders (this build).** Verified byte-identical for
   `meshdata.h`, `pc\textures.h`, `gui_bank.h`, `particles.h`, `front_end_bank.h`. Meaning: in
   the retail-patched unified build there is *no* dev/retail id drift — the retail bank slot ids
   are exactly the ones the def-compiler links against. Appends can target retail ids directly.
