# Offline runtime resource checks

From the FableTLC root, on Windows with MSVC x86 tools installed:

```powershell
python tools/script_recovery/run_meet_sister_runtime_checks.py --forge-root D:/Code/ForgeFSE-retail-shadow --output work/meet-sister-runtime-check-NEW
```

The output directory must not already exist. The runner discovers MSVC with
vswhere, or accepts `--vcvars PATH_TO_VCVARS32.BAT`. It compiles vendor Lua from C
sources and the harnesses from C++, with no dependency on existing objects or
response files. It does not launch or modify Fable.

`result.json` records input hashes, the compiler identity, command exit codes,
output hashes and the complete expected 14-scenario/255-event comparison.
Per-command logs include compiler version output. Any setup/build/test failure,
missing expected output or source change during the run returns exit code 1.
Existing output directories are rejected without overwriting their reports.

`retail_resources_smoke.cpp` checks the actual resource wrapper's ownership and
error handling. `meet_sister_cpp_integration.cpp` runs the actual staged Lua and
adapter through that wrapper and vendor sol/Lua. Engine entry points and Quest
operations are doubles. These checks do not establish native scheduler,
streaming, rendering, audio or in-game quest behavior.

`conversation_bool_operands.cpp` also checks the actual vendor sol conversion
(`0` becomes true, `false` stays false) and evaluates the boolean expressions
from all 17 New Oakvale conversation-creation call sites. This catches numeric
zero accidentally reintroduced into a C++ bool parameter. It does not execute
the conversation engine or identify audible speech.

Native expected events come from
`refs/script_recovery/meet_sister/runtime_evidence/native-lua-flow-comparison-20260912.json`.
Review changes to that evidence independently; do not regenerate expectations
from the implementation under test.

The resource smoke check also verifies explicit-resource Speak/task dispatch
against two distinct expert objects, all speech operands, nil targets and empty,
released, wrong-kind and closed handles. These calls use the actual registered
sol methods; expert engine functions are doubles. Native wrapper evidence is in
guardian_trophy_dealer_info/runtime_evidence/native-resource-dispatch-20260912.json.

`retail_thing_condition.cpp` checks actual scoped Thing operations and the extracted
alive-condition binding. `guardian_cpp_integration.cpp` loads the actual Guardian
reference/adapter and compares all 28 native full-body cases (1,377 events).
Together these bring the runner to nine binaries. The expected Guardian cases
are generated by guardian_runtime_cases.py from independent native evidence;
ordinary Quest/actor engine methods and actual fiber switching remain doubles.
